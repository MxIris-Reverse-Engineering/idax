C++ surface: new `ida::instruction::BranchCondition` enum (21 cases including `Always` / `None` / `Zero` / `NotZero` / `CountZero` / per-signedness comparisons / `Parity` / `Negative` / `Overflow`), `Instruction::branch_condition()` accessor, and free function `ida::instruction::branch_condition(Address)`. Implementation is mnemonic-based (`parse_branch_condition_from_mnemonic` in `src/instruction.cpp`) so it works on ARM64 `B.<cc>` / `CB[N]Z` / `TB[N]Z`, x86 `J<cc>` / `JCXZ` / `LOOP*`, and ARM32 `B<cc>` patterns without touching processor-specific SDK internals. Populated lazily into `Instruction` value snapshots during `populate`. Shim: `IdaxInstruction.branch_condition` field + free `idax_instruction_branch_condition`. Swift: `BranchCondition` enum, `Instruction.branchCondition` field, `Instruction.branchCondition(at:)` static query.
  - 16.157.3. Added ctree parent accessors to the handle-based ctree binding. C++ already provided `ExpressionView::parent()` / `StatementView::parent()` returning `Result<std::optional<CtreeItemView>>`, but the shim's `IdaxCtreeExprHandle` / `IdaxCtreeStmtHandle` are bare `void* raw` pointers that lose the `parents_` shared_ptr when ExpressionView is reconstructed for accessor queries. Implementation: in `idax_ctree_visit` / `idax_ctree_visit_ex` enabled `VisitOptions::track_parents = true`, recorded `expr.parent()` / `stmt.parent()` into a per-visitor `unordered_map<const void*, CtreeItemView>` keyed by `raw_handle()`, and exposed the active map via a `thread_local` pointer with RAII save/restore (`CtreeParentMapScope`). - **16.158. C ABI Shim Header Unification — Single Source for Rust + Swift Bindings**
  - 16.158.1. Background: The shared C ABI for the shim historically existed as two copies, `bindings/rust/idax-sys/shim/idax_shim.h` and `bindings/swift/Sources/CIDAX/include/idax_shim.h`, kept in sync by hand. Cross-checking the two prior to 16.157 surfaced that the copies had silently diverged — the Rust copy carried Local-Types fields on `IdaxPluginActionContext` (`type_ref_name`, `type_ref_type`), Hex-Rays session and lvar-snapshot handles, the path domain helpers, the `idax_database_idb_path` accessor, `idax_function_set_prototype`/`apply_decl`, and `idax_type_parse_declarations`; the Swift copy carried `idax_sync_ida_globals`, SE-0447 `__counted_by`/`__noescape` annotations on byte/string/array writer functions, and the LIR/HIR exposures from ledger 16.157. Neither copy was a strict superset of the other; the synchronisation discipline had failed by drift.
  - 16.158.2. Unification: Moved the canonical declarations to a neutral location at `bindings/c/include/idax_shim.h` constructed as a **superset** of both prior copies. Concretely: started from the Rust copy (broader API surface) and folded back in Swift's `idax_sync_ida_globals` declaration, the SE-0447 bounds-safety annotations on every byte/string/address-array writer (`idax_database_memory_to_database`, `idax_data_write_bytes`/`idax_data_patch_bytes`, `idax_comment_set_anterior_lines`/`idax_comment_set_posterior_lines`, `idax_loader_memory_to_database`, `idax_debugger_write_memory`, `idax_storage_node_blob_set`/`idax_storage_node_sup_set`, `idax_lumina_pull`/`idax_lumina_push`), and the LIR/HIR exposures from 16.157 (`IdaxOperand.is_read`/`is_written`, `IdaxInstruction.branch_condition`, `idax_instruction_branch_condition`, `IdaxCtreeItemInfo`, `idax_ctree_expr_parent`/`idax_ctree_stmt_parent`).

- **F11. Swift Batch 4 — IDC script 域**
  - F11.1. 新增 44 个函数，是全部批次里唯一需要真正设计所有权的域。至此 313 个缺口已补 174 个。
  - F11.2. `ScriptValue` 是 `~Copyable`（句柄 owning，`deinit` 释放）。查 shim 实现确认三个 setter（`set_attribute`、`replace_slice`、`set_global`）都是**借用**——它们解引用句柄后由 C++ 拷贝，调用方保留所有权，所以这些参数标 `borrowing`。
  - F11.3. `ScriptArguments` 存在的原因是 `~Copyable` 值进不了 `Array`。它以 `consuming` 接管每个值的所有权并在 `deinit` 统一释放，调用方不必让各个值跨调用存活。
  - F11.4. `ScriptExecutionResult.takeValue()` 用 `mutating` 而非 `consuming`：`discard self` 要求全部存储属性 trivially-destroyed，而它含 `String`。改成把句柄置 nil，`deinit` 据此跳过释放；副作用是取值后仍能读 `succeeded` 与 `error`，反而更好用。
  - F11.5. 六个测试先红后绿，全部是我对 IDC 语义的假设错误，非绑定缺陷：`coerce_string` 的输出格式不是契约（C++ 测试也只断言非空）；`compile_snippet` 是无参函数体，带参函数要用 `compile_text` 声明；`function_names` 枚举的是 IDC 注册/内置函数，不含刚编译的片段，且 `maximum` 为 0 会被拒；`reference_global` 对不存在的全局**失败而非创建**——最后一条我原先的文档注释写反了，已改正。
